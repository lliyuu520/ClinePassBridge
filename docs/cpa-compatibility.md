# CPA 兼容性说明

ClinePassBridge 使用 JSON ABI v1，按 [README](../README.md#安装与配置) 安装到支持动态库插件的原版 CPA。插件功能以原版接口为边界，升级时备份插件目录、CPA 凭据目录与插件数据目录即可。

## 原版接口与提前截流

原版 CPA **v8.0.13** 已提供 `host.http.stream_close`，**v8.0.29** 也沿用该接口，插件可主动关闭上游流。「流式卡住时提前截流」从 v0.3.2 起提供，可在原版宿主上独立使用。

当前默认关闭，默认空闲阈值仍为 20 秒。首次安装或配置缺少字段时使用默认值；显式保存的 `true`、`false` 和自定义秒数在升级、重启后继续保留。开启后从首段有效输出后计时；思考、正文和工具增量重置计时，heartbeat、role 和空帧不重置，下游发送耗时不计入空闲时间。适用于上游 SSE 请求，包括非流式聚合；原生非流式不适用，也不缩短首字等待。Debug 另有独立开关，默认关闭，按需采集额外流诊断。配置见 [进阶配置](configuration.md#流式卡住时提前截流)。

统一错误规则使用原版 CPA 的 `request_scoped_errors`。已有凭据中的该字段继续保留；显式保存统一规则时按所保存规则更新。插件在编码错误前，按原始状态和脱敏错误正文匹配当前统一规则，首条命中生效；未命中时使用下述默认策略。

## 错误状态与客户端重试

「重试兼容」默认开启，将已识别的指定 Fireworks/LiteLLM 响应截断规范为：

```text
HTTP 502: upstream response stream ended before completion: unexpected EOF (upstream_transport_incomplete)
```

插件统一判断故障归属、是否新增宿主冷却，以及当前请求是否结束。默认将普通服务、网络、协议、本地生命周期和未知故障视为免新增账号/模型冷却；明确鉴权、套餐额度、团队限流和模型能力故障保留对应保护，包括外层 502 内携带的明确受保护状态。确定的参数、上下文长度和大小限制错误会结束当前请求，避免换账号重复提交同一错误输入。已有额度暂停、团队窗口和出口预算独立生效。

普通 HTML/plain 路由 404 归为服务路由故障；明确 `model_not_found` 或模型不支持仍保留模型范围的保护。HTTP 403 只有明确的 Cloudflare challenge 响应头或 HTML 特征才归出口故障；普通 403 及真实 JSON 鉴权错误保留原保护。使用本地出口池时，挑战响应冷却对应出口组；沿用宿主 HTTP 回调时仅做错误归属和宿主冷却兼容，插件不管理该宿主出口。诊断保留原始 HTTP 404/403，兼容响应使用内部 502 分类。

宿主冷却兼容与 `client_retry_compatibility` 开关独立。开启时规范上游服务/协议/连接错误，避免原始嵌套状态误导客户端；关闭时尽量保留原文，但宿主分类标签、生命周期文本和受保护错误摘要仍生效。原始诊断始终留在插件日志。

已核对的原版 CPA v8.0.13、v8.0.29 流错误接口只传字符串。未命中插件统一规则的普通服务/未知故障使用 EOF/timeout 识别词或明确的 `[clinepassbridge:cpa_compat:...]` 标签，并在对应 RPC 错误中省略内部 `http_status`（0 表示缺失）；除下述 Chat Completions 兼容结构外，下游由 CPA 默认封装为 500（通常为 `internal_server_error`），已开始的 HTTP 200 通过 SSE error 结束，插件日志保留内部状态。宿主仅按 500/502 状态配置的规则可能匹配不到这类兼容错误。兼容标签仅用于宿主分类，不表示已经确认底层断流原因。

「重试兼容」开启时，仅原始路径 `/v1/chat/completions` 在 `after_output` 阶段、明确归为请求范围的 5xx，且无显式规则、冷却或停止策略时，向 `host.stream.close` 的 `error` 字符串传递单行 JSON，包含 `error.type="server_error"`、`error.code="500"` 及保留原兼容摘要和分类标签的 `message`。适用错误仅为 `upstream_service_error`，或内部网络子类型为 `eof` 的 `upstream_network_error`；EOF 来自传输错误类型、流完整性检查或已验证的结构化回调，不通过 message 推断，未知网络故障、连接重置/关闭、超时、DNS 和 TLS 错误均沿用原编码。原版 CPA v8.0.29 会透传该 JSON；`500` 是兼容业务码，实际 HTTP 200、日志中的原始状态/异常和 `error_details` 的真实 code/status 不变。RPC、其他接口、缺少路径、关闭开关和未满足条件的流错误沿用原编码与回退。

本机安装的 ZCode 3.16.2 解析链与分类函数已离线验证该结构可归为 `server_error`、`retryable=true`；已输出内容的恢复仍由客户端根据输出/工具状态和重试预算处理，尚未完成整客户端交互验收。插件不会因此新增上游请求或透明重放，也不表示上游故障已修复。

确定的请求错误在 RPC 和流错误文字中携带 `invalid_request_error` JSON，供已核对的宿主停止同请求轮换并跳过新增冷却；流内 400/422 等也通过该结构保留请求错误语义。本地响应/帧/前导大小超限仍单列为 `response_limit_exceeded`（413）和 `message_too_big`。这与上述省略 RPC 状态的服务故障兼容路径不同。取消、截止时间和插件关闭也按请求生命周期处理。插件不自动重放已输出的内容，也不清除已有冷却。

命中插件统一规则时，RPC 保留可供 CPA 匹配的状态和正文，继续由宿主执行停止/继续及强制冷却动作。纯字符串流边界由插件编码规则的免冷却或冷却选择；强制冷却的具体状态和重试时间在原版接口中仍会丢失，时长按宿主实际结果处理。已输出的流以错误结束；首段输出前的 RPC 返回仍由 CPA 按规则决定是否换路由。规则只影响宿主错误处理，不撤销插件的真实额度、团队或出口窗口。

已有 `error-rules.json` 和显式规则保持原样，无需重写旧配置。空规则数组继续表示继承 CPA；宿主全局规则没有公开读取接口，不参与插件的本地预匹配，只有宿主实际收到并匹配的规则才生效。未命中的普通故障使用状态缺失的兼容编码，宿主仅按 500/502 状态配置的规则可能匹配不到，应在插件统一规则中显式设置所需动作。

CPA 可在首段输出前按自身请求重试预算重试；客户端也按自身配置决定重试。已核对的 DSH 源码 `d743267388641bc76f17c45ce8b4c231aed1d32c` 将规范文案归为可重试的 `SERVER`，实际受重试组件、策略和预算约束。插件不自动重放已开始的输出。

兼容性核对覆盖原版 CPA **v8.0.13、v8.0.29** 的 RPC、字符串流错误及冷却判定路径，并以受控故障样例验证；官方 v8.0.29 镜像也已完成插件加载检查。这些证据覆盖已测分类与调用路径，不代表所有瞬时故障均已在生产环境验证免冷却。插件同时针对 v8.0.29 新增的 HTTP/2 关闭识别词隔离受保护错误。

原版 CPA v8.0.13、v8.0.29 的插件链路不应用全局 payload 规则；插件安装与发布不依赖宿主定制。需要调整思考强度时，使用客户端参数或插件的思考强度映射。

## Token 计数

`/v1/messages/count_tokens` 当前由插件本地返回 HTTP 404，表示计数端点尚未实现。已核对的原版 CPA v8.0.13、v8.0.29 会将这类端点 404 记录为计数失败，但默认不因本次失败新增账号/模型冷却，普通生成仍可继续调度。该处理与「重试兼容」开关无关；已有冷却保留，显式配置的强制冷却规则仍按宿主规则生效。

此兼容处理尚未提供本地 token 估算或上游精确计数；实际用量继续使用生成响应中的 `usage`。

## 冷却与网络分类

请求仍计为失败，已有 CPA 冷却和团队退避保留；团队恢复探测遇已分类的请求/服务故障时只释放探测槽，不将其当成团队再次限流。其他宿主版本需重新核对错误识别与调度行为，实际冷却以 CPA 返回的状态为准。见 [调度说明](scheduling.md#响应截断与模型冷却)。

独立网络路径保留网络、取消和截止时间的错误类型；原版 HTTP 回调缺少类型信息时按回调来源记为 `upstream_callback_error`，不据此断言 DNS、TLS 等具体原因。文本回调仅在错误全文或结尾精确匹配 `context canceled` / `context deadline exceeded` 时识别为 499 / 504。已收到的鉴权、额度、限流 HTTP 状态优先于读取正文时的网络失败。完整诊断保留在日志；受保护错误原文若含宿主传输识别词，对宿主使用受控摘要，避免反向误豁免。

## 可选字段的被动兼容

运行实现保留对 `error_details`、`error_details_supported`、`model_states_available` 和 `model_states` 等可选字段的兼容读取。仅在宿主实际提供时使用这些信息，原版安装流程不依赖它们。

宿主未确认结构化流错误支持时，日志中的 `legacy_host_unknown` 仍表示处理结果未获宿主确认；文本识别兼容不提供这种确认，因此该值不代表兼容失效，也不应仅据识别词改记为已确认豁免。实际冷却以 CPA 状态为准。未提供模型范围时，账号卡片显示「调度受限」。
